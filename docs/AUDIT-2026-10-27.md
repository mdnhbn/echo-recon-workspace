# Echo Recon project audit — 27 October 2026

[বাংলা report](AUDIT-2026-10-27.bn.md) · [macOS setup](MACOS.md) · [Security model](../SECURITY.md)

## Result and scope

This internal engineering review started from **6.7.0, commit `584b35df7b83fe60b022981e68d902ac028442f1`**, following completion of native macOS support. The corrective release is **6.7.1**. This is a source, installation, runtime and release review, not an independent penetration-test certificate or a guarantee that third-party scanners find every issue.

Reviewed: all nine fixed tool adapters; target/URL/scope validation; process execution and cancellation; SQLite history and exports; local HTTP/session boundaries; browser scripts/templates; Linux, Windows and macOS setup; dependency pins; launch/update paths; Debian packaging and signed APT publishing; CI and contributor/user documentation. No public target was assessed, no API accounts were created, and no production history was modified for this audit.

## Findings and corrections

Severity describes this application's operational/privacy impact, not a CVSS score. References point to the corrected implementation; the baseline commit above preserves the original evidence.

| ID / severity | Confirmed condition and impact | Correction / regression evidence |
|---|---|---|
| A01 — Medium | On Linux/macOS, a child could ignore SIGTERM and redirect stdout/stderr. The leader exited, so waiting for the leader and pipe readers did not prove the child had stopped. The tool could remain active after Stop or normal leader exit. | [runner.py](../echo_recon/runner.py) now cleans the owned process group even after leader exit. [POSIX regressions](../tests/test_posix_cleanup.py) use real ignoring children and confirm an unrelated group survives. Windows Job Object behavior remains intact. |
| A02 — Medium | Linux/Windows explicit Nuclei template setup used `-update-templates -duc`. The pinned engine's disable-update flag also suppressed the requested template update; an installed engine could still lack usable templates. | Remove `-duc` only from explicit updater calls in [Linux](../setup_tools.py) and [Windows](../setup_tools_windows.py). Diagnostic/assessment commands still disable automatic updates. Kali, portable-Linux, Windows and Nuclei health tests cover these distinct commands. macOS already used the correct updater. |
| A03 — Medium | The publisher replaced its package pool without comparing the incoming Debian version to existing packages. It could publish an older version as the only feed candidate. | The current publisher calls [check-feed-version.sh](../packaging/check-feed-version.sh) before pool/metadata mutation. [Five archive tests](../tests/test_release_feed.py) use real `.deb` files and numeric Debian ordering. Equal versions retain the existing byte-identical idempotency check. **Historical workflows remain a residual risk; see below.** |
| A04 — Medium | A first APT-style launch failed if the parents of the configured user data directory did not exist. `mkdir` ran before the later recursive creation path. | [app.py](../app.py) creates missing parents before taking the lock. [Fresh-user startup test](../tests/test_startup_data.py) reaches the app boundary using a new nested folder without starting a listener or scanner. |
| A05 — Medium | Best-effort redaction masked only the first token of common HTTP credential headers; a Bearer credential or later Cookie field could remain in saved/exported evidence. | [security.py](../echo_recon/security.py) removes the entire Authorization, Proxy-Authorization, Cookie and Set-Cookie header value before generic redaction. [Header regressions](../tests/test_redaction_headers.py) retain adjacent ordinary lines and reject leftover fake credentials. This does not retroactively rewrite old reports. |
| A06 — Low | User key-verification instructions depended on private repository Settings; contribution/issue text referred to removed demos or outdated setup behavior; generated APT text incorrectly implied Git tags were signed. | Publish the public fingerprint in [APT instructions](APT.md); correct EN/BN contribution and issue templates. The signed object is the APT repository metadata. Git version tags are not claimed to carry cryptographic signatures. |

### Corrective release checks

The full suite includes the new POSIX child, first-user folder, credential-header and Debian feed tests. Windows intentionally skips native POSIX/macOS/Debian cases and privileged symlinks unavailable to the normal user. Linux/macOS CI executes the appropriate native cases. See the [6.7.1 release checks](https://github.com/mdnhbn/echo-recon-workspace/actions) for the version tag's final status, rather than treating a platform skip as a pass.

Local Windows Python 3.14 result after the corrections: **178 tests discovered, 163 passed, 15 skipped, no failures**. Native platform tests remain required in CI; local Windows cannot establish their outcome.

JavaScript syntax, Bash/PowerShell entrypoint checks, Debian package construction, Python regressions and whitespace checks are part of validation. Installer fixtures mock package managers/downloads unless explicitly identified as a native integration check above. A package build/inspection is not a full fresh Kali package-install test.

### Dependency and secret-signature checks

- `pip-audit 2.10.1` queried the advisory service for the seven exact dashboard packages in `requirements.txt` using `--require-hashes --disable-pip`. **No known vulnerabilities were returned** for Flask 3.1.3, blinker 1.9.0, click 8.5.0, itsdangerous 2.2.0, Jinja2 3.1.6, MarkupSafe 3.0.4 and Werkzeug 3.1.9 on this audit date. [Saved machine-readable result](audit-evidence/2026-10-27-dashboard-dependencies.json).
- A bounded signature check over the baseline's 74 tracked working-tree files found no matching private-key blocks, GitHub tokens, AWS access-key IDs or Google API-key signatures. This was not a complete Git-history, remote-secret, ignored-file or general credential audit. Secret values were not included in the audit output.
- This dependency result covers the dashboard lockfile, **not** every dependency inside the nine scanners, Homebrew/OS packages, templates or previously installed environments.

## Safeguards retained

- Listener restricted to `127.0.0.1:8001`, local-client and Host checks, same-site session and CSRF checks for state changes, escaped reports and a restrictive browser content policy.
- Fixed argument arrays with no shell interpolation; exact authorized host scope; public-DNS preflight; discoveries do not automatically expand active scope.
- Honest missing/unverified/error/partial/cancelled/output-limit states, persistent history, interrupted-run marking and single-instance/setup locks.
- Verified pinned binary/source downloads, bounded archive extraction, isolated managed Python environments, preservation of unknown/partial folders and no automated root/elevation bypass.
- Static light/dark interfaces without Matrix animation; URL paths/ports supported for URL-aware adapters. Query strings/fragments are omitted intentionally. No assessment wall-clock deadline was reintroduced.

## Remaining limitations and recommended work

1. **Historical APT publisher replay — administrative risk.** The new version guard is in 6.7.1+ source. Rerunning an older tag executes its historical workflow, which has no guard and can still replace a newer feed. Do not rerun pre-6.7.1 publishers. Recovery is to rerun the newest matching release workflow. Old tags and credentials were not rewritten. Repository-owner workflow/credential policies would require separate administration work.
2. **Platform coverage.** Full nine-backend provisioning was tested on Apple Silicon, not every Intel Mac or macOS version. Intel/Homebrew availability depends on upstream support. Other Linux families use controlled installer fixtures; WSL/VirtualBox can run supported Linux guests, but every host/guest combination was not freshly provisioned. Android is not added by this release.
3. **Third-party reproducibility.** Dashboard dependencies are hash locked. Backend Python dependencies do not all have a complete transitive cross-platform hash lock; Homebrew/OS packages and current Nuclei templates can change upstream. Follow-up work: platform-specific reviewed dependency locks and scheduled advisory reviews.
4. **Containment and resources.** Scope/DNS preflight is not a network firewall; tools resolve DNS again and may follow links or contact providers. Output caps do not bound every scratch file. With no scan time limit, use Stop and monitor disk/network use. Readiness checks also have no wall-clock deadline. POSIX process groups do not contain deliberately session-escaping programs; Windows Job Objects have different semantics.
5. **Data privacy.** Redaction remains best effort. Raw crawl files, uncommon secret formats and old exports may contain sensitive information. New redaction does not clean previously saved history automatically. Review exports and use private backups/OS file permissions.
6. **No universal scan certification.** Local help/identity readiness and fixture tests do not prove live provider/API behavior, authenticated scanning, a full fresh install on every platform, or vulnerability coverage. A fresh graphical review on a physical Mac and a full new Kali APT installation remain useful follow-up acceptance checks.

## User update paths

- **macOS source installation:** stop the app, back up private `data/`, run `git pull --ff-only`, `bash install.sh`, then `bash run.sh`. Native Homebrew and Python 3.12+ are prerequisites; see [English](MACOS.md) / [বাংলা](MACOS.bn.md).
- **Kali APT installation:** after the signed feed is configured, `sudo apt update && sudo apt upgrade`. This applies only after successful publication of the version tag and does not update a separate source checkout.
- **Windows source installation:** stop the app, back up data, pull the repository, then use `install.ps1` and `run.ps1` as described in [WINDOWS.md](WINDOWS.md). macOS APT commands do not apply.

The original protected Windows workspace did not accept file writes during the corrective work. A separate Git clone was used for changes and tests; original project files and private data were preserved. The published repository is the delivery source, not a claim that every already installed local copy has been upgraded automatically.
